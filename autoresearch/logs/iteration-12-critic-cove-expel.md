# 迭代 12: CRITIC / CoVe / ExpeL 方法深入

## 12.1 CRITIC：工具增强的自我批评

### 基本信息
- **论文**: CRITIC: Large Language Models Can Self-Correct with Tool-Interactive Critiquing
- **arXiv ID**: 2305.11738
- **发表**: ICLR 2024
- **核心创新**: 用外部工具验证 LLM 输出，而非纯自我批评

### 核心洞察
人类用外部工具检查和改进工作：
- 搜索互联网验证事实
- 用代码解释器调试程序
- 用计算器验证数学

LLM 也应该如此：**外部反馈 > 内部自我判断**。

### 工作流程

```
初始输出 → 工具验证/批评 → 基于反馈修改 → 最终输出
    ↑                             ↓
    └────── 迭代 N 轮 ────────────┘
```

### 关键设计

#### 1. 批评即验证
不是让 LLM 问自己"对吗？"（不可靠），而是：
- **事实性** → 搜索引擎验证
- **代码正确性** → 代码解释器执行
- **数学正确性** → 计算器验证

#### 2. 渐进式修改
不重写整个答案，而是基于验证反馈针对性修改。

### 实验结果

评测任务：
1. **自由形式问答** — 用搜索引擎验证
2. **数学程序合成** — 用代码解释器验证
3. **毒性减少** — 用分类器验证

结果：**CRITIC 在所有任务上一致提升 LLM 性能**。

### 核心启示
**外部反馈对 LLM 自我改进至关重要** — 这验证了报告中"评测反馈信号不足"是进化瓶颈的判断。CRITIC 通过引入工具反馈解决了这个问题。

## 12.2 Chain-of-Verification（CoVe）：链式验证减少幻觉

### 基本信息
- **论文**: Chain-of-Verification Reduces Hallucination in Large Language Models
- **arXiv ID**: 2309.11495
- **机构**: Meta AI
- **核心创新**: 四步验证流程，系统性地检查事实错误

### 四步流程

```
步骤1: 草拟初始回答
  └─ "XXXX 是什么？" → 初始答案

步骤2: 计划验证问题
  └─ 生成需要核实的问题列表
  └─ "答案中提到的 Y 是真的吗？"

步骤3: 独立回答验证问题
  └─ 关键：不参考初始答案（避免偏差）
  └─ 逐个独立回答验证问题

步骤4: 生成最终验证后的回答
  └─ 基于验证结果修正初始答案
```

### 关键设计：独立性

**最重要的一点**：验证问题的回答必须**独立于初始答案**。

为什么？如果验证时能看到初始答案，会倾向于确认它（确认偏差）。独立验证才能发现真实错误。

### 实验结果

评测任务：
- Wikidata 列表问题
- 闭卷 MultiSpanQA
- 长文本生成

结果：**显著减少幻觉**。

### 与 CRITIC 的对比

| 维度 | CRITIC | CoVe |
|------|--------|------|
| **验证源** | 外部工具 | LLM 自身知识 |
| **适用场景** | 事实/代码/数学 | 纯知识问答 |
| **成本** | 需要工具调用 | 仅 LLM 调用 |
| **独立性** | 工具中立 | 需要设计独立性 |
| **核心机制** | 工具反馈循环 | 自问自答验证 |

## 12.3 ExpeL：经验学习 Agent

### 基本信息
- **论文**: ExpeL: LLM Agents Are Experiential Learners
- **arXiv ID**: 2308.10144
- **发表**: AAAI-24
- **核心创新**: 从经验中提取自然语言洞察，无需参数更新

### 问题动机

- 微调成本高，且可能损害泛化能力
- GPT-4、Claude 等顶级模型只有 API，权重不可用
- 需要一种"无参数更新"的学习方法

### 工作机制

#### 训练阶段：经验收集与洞察提取
```
1. 在训练任务集上自主执行任务
2. 收集成功和失败的经验
3. 从经验中提取自然语言洞察：
   - 成功案例："当 X 时，做 Y 是有效的"
   - 失败案例："不要做 Z，因为会导致 W"
4. 洞察存储到经验库
```

#### 推理阶段：经验复用
```
1. 接收新任务
2. 检索相关洞察和经验
3. 将洞察作为指导融入决策
4. 执行任务
```

### 关键特性

1. **一致性提升** — 随经验积累，性能持续提升
2. **迁移能力** — 洞察可以迁移到新任务
3. **无需微调** — 纯自然语言，零参数更新
4. **自主性** — Agent 自主决定学什么

### 与 Reflexion 的对比

| 维度 | Reflexion | ExpeL |
|------|-----------|-------|
| **学习范围** | 单任务内反思 | 跨任务洞察 |
| **存储内容** | 反思文本 | 抽象洞察规则 |
| **抽象层次** | 具体（针对特定失败）| 抽象（可迁移规则）|
| **训练阶段** | 无（边做边反思）| 有（专门收集经验）|
| **迁移能力** | 弱 | 强 |

### 核心启示

ExpeL 证明了**从具体经验中提取抽象规则**是可行的——这正是报告中"经验复用的泛化难题"的一个潜在解法。

## 12.4 三种方法的定位总结

```
自我修正方法谱系（按验证源排序）
│
├── 纯内部验证
│   └── Self-Refine — 自己批评自己
│       优点：零成本
│       缺点：不可靠（确认偏差）
│
├── 结构化内部验证
│   └── CoVe — 独立问题验证
│       优点：减少确认偏差，无需工具
│       缺点：仍受模型知识限制
│
├── 外部工具验证
│   └── CRITIC — 工具增强批评
│       优点：可靠的验证信号
│       缺点：需要工具生态
│
└── 跨任务经验学习
    └── ExpeL — 洞察提取+复用
        优点：可迁移、持续提升
        缺点：需要训练任务集
```

### 组合使用建议

1. **事实性任务** — CoVe（独立验证）+ CRITIC（搜索验证）
2. **代码任务** — CRITIC（执行验证）+ Reflexion（反思改进）
3. **长期部署** — ExpeL（积累洞察）+ GEPA（进化 Prompt）
4. **最佳实践** — 内部验证快速筛选 + 外部验证确保可靠 + 经验积累长期提升

---

## 核心启示

1. **验证源决定上限** — 纯自我批评 < 结构化验证 < 外部工具验证
2. **独立性是关键** — 验证必须独立于被验证的内容
3. **抽象是迁移的前提** — ExpeL 的洞察提取解决了经验泛化的核心难题
4. **组合策略是方向** — 不同任务需要不同的验证组合
