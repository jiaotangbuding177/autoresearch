# 迭代 11: DSPy 框架与 GEPA 深入调研

## 11.1 DSPy：声明式 LM 编程框架

### 基本信息
- **论文**: DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines
- **arXiv ID**: 2310.03714
- **机构**: Stanford NLP
- **仓库**: https://github.com/stanfordnlp/dspy
- **核心创新**: 将 LM 管道抽象为"文本转换图"，通过编译器自动优化

### 核心思想

#### 从"Prompt 工程"到"Prompt 编译"
```
传统方式：人工设计 Prompt → 试错调整 → 最终 Prompt
DSPy 方式：声明式定义任务 → 编译器自动优化 → 最优 Prompt + 示例
```

#### 三大核心概念

1. **Signatures（签名）** — 声明输入输出结构
   ```python
   class QA(dspy.Signature):
       """回答问题"""
       question = dspy.InputField()
       answer = dspy.OutputField()
   ```

2. **Modules（模块）** — 可组合的推理单元
   - `dspy.Predict` — 基础预测
   - `dspy.ChainOfThought` — 链式思维
   - `dspy.ReAct` — 推理+行动
   - `dspy.ProgramOfThought` — 代码生成执行

3. **Optimizers（优化器）** — 自动优化模块参数
   - 生成 Few-shot 示例
   - 优化指令措辞
   - 联合优化（示例+指令）

### 关键结果

| 基准 | DSPy 编译后 | 基线 | 提升 |
|------|-------------|------|------|
| 数学应用题 | 显著提升 | 标准 Few-shot | +25% |
| 多跳检索 | 显著提升 | 专家示例 | +5-46% |
| 复杂问答 | 显著提升 | 标准 prompting | +65% |

**突破性发现**：编译后的 770M T5 小模型可以媲美使用 GPT-3.5 的专家 Prompt 链。

### 核心价值

1. **解耦任务与实现** — 声明"做什么"，编译器决定"怎么做"
2. **自动化优化** — 无需人工试错 Prompt
3. **模型无关** — 同一程序可编译到不同模型
4. **可组合** — 模块可以像 LEGO 一样组合

## 11.2 DSPy 优化器详解

### 优化器谱系

```
DSPy 优化器
│
├── Few-shot 优化
│   ├── BootstrapFewShot — 引导示例生成
│   ├── BootstrapFewShotWithRandomSearch — 随机搜索版本
│   └── KNNFewShot — KNN 检索示例
│
├── 指令优化
│   ├── COPRO — 坐标上升优化指令
│   └── MIPROv2 — 贝叶斯优化指令+示例
│
└── 反思进化
    └── GEPA — 遗传-帕累托反思进化
```

### MIPROv2（Multi-stage Instruction PRoposal Optimizer v2）

#### 三阶段流程
```
阶段1: Bootstrap 示例生成
  └─ 用当前管道在训练数据上生成成功轨迹

阶段2: Grounded 指令建议
  └─ 基于数据感知的摘要，为每个模块生成指令候选

阶段3: 贝叶斯超参优化
  └─ TPE 搜索（Optuna）联合优化指令+示例+示例数量
```

#### 特点
- **数据感知** — 指令建议基于实际数据分布
- **联合优化** — 指令和示例同时优化
- **贝叶斯搜索** — 智能探索参数空间
- **成本可控** — 可设置预算限制

### BootstrapFewShot

#### 工作原理
```
1. 用当前管道在训练集上运行
2. 收集成功的执行轨迹
3. 保留成功的轨迹作为 Few-shot 示例
4. 用增强后的示例重新构建 Prompt
```

#### 特点
- **简单快速** — 只需一次编译运行
- **效果显著** — 通常能提升 10-30%
- **适用场景** — 有标注数据、任务明确

### COPRO（Coordinate Ascent）

#### 工作原理
```
对每个模块的指令：
  1. 生成指令的多个变体
  2. 评估每个变体的性能
  3. 选择最优变体
  4. 固定该模块，优化下一个
```

#### 特点
- **逐步优化** — 一次优化一个模块
- **可解释** — 可以看到每步的改进
- **适合小规模** — 模块数量少时效果好

## 11.3 GEPA：反思式 Prompt 进化（2025 突破）

### 基本信息
- **论文**: GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning
- **arXiv ID**: 2507.19457
- **发表**: ICLR 2026 (Oral)
- **仓库**: https://github.com/gepa-ai/gepa

### 核心创新
用**自然语言反思**替代**策略梯度**进行 Prompt 优化。

#### 与传统 RL 的对比

| 维度 | 传统 RL (GRPO) | GEPA |
|------|----------------|------|
| **学习信号** | 标量奖励 | 自然语言反思 |
| **更新方式** | 策略梯度 | Prompt 进化 |
| **样本效率** | 需要大量 rollout | 最多减少 35 倍 |
| **可解释性** | 低（梯度是黑盒）| 高（反思是人类可读的）|
| **核心机制** | 参数更新 | 语言诊断+修复 |

### 工作原理

```
1. 采样轨迹
   └─ 推理步骤、工具调用、工具输出

2. 语言反思
   └─ 用自然语言诊断问题："这里失败是因为..."

3. 提出 Prompt 修改
   └─ 基于诊断提出具体的 Prompt 改进

4. 帕累托前沿组合
   └─ 组合多个成功尝试的洞察（遗传算法思想）
```

### 关键结果

| 对比 | 结果 |
|------|------|
| vs GRPO（6 个任务） | **+6% 平均，最高 +20%** |
| 样本效率 | **最多减少 35 倍 rollouts** |
| vs MIPROv2 | **+10% 以上** |
| AIME-2025 | **+12% 准确率** |
| 代码优化 | 可作推理时搜索策略 |

### 为什么重要

1. **语言是更丰富的学习媒介** — 比标量奖励传递更多信息
2. **样本效率极高** — 几次 rollout 就能显著提升
3. **桥接反思与进化** — 结合了 Reflexion 的反思和 Evolutionary 的进化
4. **可解释** — 人类可以理解为什么 Prompt 改进有效

### 自我进化视角的意义

GEPA 代表了一种**混合范式**：
- 反思（Reflexion 的思想）→ 诊断问题
- 进化（遗传算法的思想）→ 组合优秀变体
- 帕累托（多目标优化的思想）→ 保持多样性

这验证了报告中"组合优于单一"的判断。

## 11.4 DSPy 生态的意义

### 对 Agent 开发的影响

1. **从手工艺到工程化** — Prompt 优化从"艺术"变为"科学"
2. **可复现性** — 编译过程可复现，结果可比较
3. **模型可迁移** — 同一程序可编译到不同模型
4. **成本优化** — 小模型+优化 ≈ 大模型+手写 Prompt

### 对自我进化的启示

1. **优化器即进化机制** — DSPy 的编译过程就是一种"自我进化"
2. **需要数据集** — 进化的前提是有评估标准（metric + data）
3. **反思+搜索结合** — GEPA 证明反思与搜索可以互补
4. **帕累托前沿** — 多目标优化保持多样性很重要
