# 迭代 13: 最新基准进展调研（2025-2026）

## 13.1 τ³-bench：从文本到多模态、知识感知

### 演进路线
```
τ-bench (2024)          τ²-bench              τ³-bench (2026)
文本对话客服      →     telecom 领域拆分  →   多模态+知识感知
airline + retail       + 更多修复          + banking_knowledge
                                           + Voice 全双工音频
```

### τ³-bench 新增能力

#### 1. banking_knowledge 领域
- **检索增强客服** — 围绕 RAG 构建的客服场景
- 可配置的 RAG 管道
- 文档搜索、嵌入检索
- Agentic shell-based search（Agent 式命令行搜索）

#### 2. Voice 全双工（音频原生）
- 端到端语音评测
- 使用实时语音提供商（OpenAI、Gemini、xAI）
- 真实语音对话场景（非文本转录）

#### 3. 75+ 任务修复
基于 SABER 研究（Cuadron et al., 2025）修复：
- 错误的预期动作
- 不清晰的指令
- 无法完成的约束
- 缺失的 fallback 行为

### 关键教训：基准也会出错

**v1.0.1 (2026年7月)** 修复了 banking_knowledge 任务错误：
- 分数变化，旧版本结果**不可比较**
- 受影响的排行榜提交被重新评分
- 教训：**基准本身的错误会传播到所有下游研究**

### 论文矩阵
- τ-Voice (arXiv 2603.13686)
- τ-Knowledge (arXiv 2603.04370)
- 任务修复论文 (arXiv 2512.07850)

### 启示
τ³-bench 的演进方向验证了报告中的判断：
1. **动态化** — 持续修复和改进任务
2. **多模态** — 从文本到语音
3. **知识感知** — RAG 是真实客服的核心

## 13.2 SWE-bench Live：持续更新的活基准

### 基本信息
- **论文**: SWE-bench Goes Live! (arXiv: 2505.23419)
- **作者**: Linghao Zhang 等
- **网站**: swe-bench-live.github.io
- **数据集**: huggingface.co/SWE-bench-Live

### 解决的核心问题

**静态基准的三大缺陷**：
1. **无发布后更新** — 数据冻结在发布时刻
2. **仓库覆盖有限** — 只有 12 个 Python 仓库
3. **人工维护重** — 每个任务需要手动构建环境

**后果**：
- 过拟合风险（模型可能"背题"）
- 数据污染（训练数据混入测试集）
- 无法反映最新能力

### SWE-bench Live 的解决方案

#### 自动化策展管道
```
真实 GitHub Issue
    ↓ 自动发现
自动实例化（提取问题+PR）
    ↓ 自动构建
Docker 环境（可复现执行）
    ↓ 自动验证
纳入基准（持续更新）
```

#### 关键数据
- **1,319 个任务**（首版）
- **93 个仓库**（vs 原版 12 个）
- 任务来自 **2024 年以后**的新 Issue
- 每个任务独立 Docker 镜像

### 关键结果

**重大发现**：即使控制条件相同，主流 Agent 框架在 SWE-bench Live 上的表现**显著低于**静态 SWE-bench。

**原因分析**：
1. 任务更新、更难（没有历史解决方案可参考）
2. 仓库更广泛（模型知识覆盖更少）
3. 无数据污染（无法"背题"）

### 意义

SWE-bench Live 证明了：
1. **静态基准可能高估能力** — 部分分数来自数据污染
2. **持续更新是刚需** — 防污染、防过拟合
3. **自动化策展可行** — 降低维护成本

这直接验证了报告中"盲区 1: 静态评测 vs 动态现实"的判断。

## 13.3 基准演进趋势总结

### 趋势 1: 从静态到动态

| 基准 | 静态版本 | 动态演进 |
|------|----------|----------|
| SWE-bench | 2,294 固定任务 | SWE-bench Live（持续更新）|
| τ-bench | airline + retail | τ³-bench（持续修复+新领域）|
| GAIA | 466 固定问题 | 计划扩展中 |

### 趋势 2: 从单模态到多模态

- τ³-bench 加入 Voice 全双工评测
- VisualAgentBench 扩展视觉能力
- 未来：视频、屏幕操作

### 趋势 3: 从纯技术到知识感知

- banking_knowledge 领域（RAG）
- 知识检索成为 Agent 核心能力
- 评测需要覆盖"知道去哪找"的能力

### 趋势 4: 从手工到自动化

- SWE-bench Live 的自动策展管道
- 自动化环境构建（Docker）
- 自动验证任务质量

### 趋势 5: 防污染成为设计目标

- 持续更新数据防背题
- 独立环境防泄露
- 时间戳验证（任务创建时间 vs 模型训练时间）

## 13.4 对研究结论的验证

### 验证 1: "评估盲区是自我进化的瓶颈"

SWE-bench Live 的发现（静态基准高估能力）直接验证了这一判断——**评测失真会误导进化方向**。

### 验证 2: "静态评测 vs 动态现实"

τ³-bench 和 SWE-bench Live 的演进（持续修复、持续更新）验证了动态评测的必要性。

### 验证 3: "多维度评测是方向"

τ³-bench 从文本扩展到语音+知识检索，验证了单一维度评测的不足。
